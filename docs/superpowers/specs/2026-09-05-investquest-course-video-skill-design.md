# InvestQuest 课程视频生产 Skill 设计

## 目标

创建项目专用 Codex Skill `investquest-course-video`，把已经在 L1-1《储蓄与复利》中验证过的制作流程固化为可复用生产线。后续课程仍保留用户对脚本、布局和成片的审核权，同时减少重复查找资产、重复解释工具和遗漏验收步骤。

Skill 面向 `/path/to/user/Desktop/Finance` 项目，不设计成通用视频制作框架。

## 成功标准

- 新课程请求能自动路由到该 Skill。
- 课程脚本必须覆盖对应题目所需信息，并与前后课程自然衔接。
- 画面复用现有画风、小啾骨骼资产、布局编辑器和 HyperFrames 工程规范。
- 用户提供剪映 AI 旁白后，可以按真实语速同步分镜、知识元素、嘴型和眨眼。
- 渲染前能统一检查画面、音频、时长、比例和必要文件。
- 上传 R2、更新网站、提交或推送 GitHub 仅在用户明确要求后执行。

## 采用方案

采用“流程 Skill + 模板 + 自动验收脚本”。

不采用纯文档方案，因为它无法稳定减少重复检查；暂不开发完整课程视频生成器，因为当前各课程的知识图形和分镜仍需要人工判断，过早抽象会增加维护成本。

## Skill 结构

Skill 安装到：

`/path/to/user/.codex/skills/investquest-course-video/`

包含：

- `SKILL.md`：触发范围、阶段路由、关键约束和交付规则。
- `references/workflow.md`：完整生产流程及各阶段的输入、输出和审核门槛。
- `references/project-map.md`：Finance 项目内的规范、模板、角色、编辑器、旁白和发布文件位置。
- `references/quality-gates.md`：内容、画面、动画、音频、渲染和网站集成检查表。
- `assets/episode-workbook-template.md`：新课程的课程资料工作簿模板。
- `scripts/validate_episode.py`：对课程工程和最终媒体执行确定性检查。
- `agents/openai.yaml`：Codex 中显示的名称、简介和默认提示。

## 触发边界

以下请求应触发 Skill：

- 制作 InvestQuest 的下一节课程视频。
- 修改课程脚本、分镜、画面布局或动效。
- 把剪映旁白同步到课程动画。
- 检查、渲染、发布或替换课程视频。
- 复用或调整小啾老师在课程视频中的动作。

独立的小啾资产编辑仍以 `video/shared/xiaojiu-rig` 为准；非 InvestQuest 项目的视频不触发本 Skill。

## 输入与产物

### 必要输入

- 课程编号与标题。
- 对应课程正文或知识目标。
- 该课程后续题目、答案与解释。
- 上一课结尾和下一课主题，用于课程衔接。

### 分阶段产物

1. 课程工作簿：题目覆盖矩阵、金融表述风险、课程承接关系。
2. `narration.md`：完整旁白，画面中不直接展示全文。
3. `STORYBOARD.md`：分镜时长、知识动作、屏幕关键词和小啾动作。
4. HyperFrames 工程与可访问预览。
5. 用户调整后导出的布局 JSON。
6. 剪映生成的 AI 旁白音频及对应时间数据。
7. 检查通过的 MP4。
8. 经用户确认后的 R2 地址、网站引用和 Git 提交。

## 制作流程

### 1. 内容校准

先读取课程和题目，建立“题目考点 → 旁白段落 → 分镜”的覆盖关系。所有数值示例必须标明适用条件；涉及收益、风险、期限、流动性和制度的表述必须避免过时或保证性措辞。脚本确认前不进入动画制作。

### 2. 脚本与分镜

旁白使用“承接上一课 → 提出问题 → 建立概念 → 演示机制 → 回答题目 → 行动总结 → 引出下一课”的结构。分镜数量由内容决定，现有八分镜只是 L1-1 的参考，不作为硬性要求。

每个分镜只展示标题、关键词、数字、公式或图标，不放完整旁白字幕。每一个知识图形必须服务于旁白中的一个具体概念。

### 3. 画面和角色

以 `docs/ANIMATION_STYLE_GUIDE.md` 和已确认课程设计为视觉基准。使用暖白纸张、深蓝手绘线、低饱和金融色彩、SVG 逐笔绘制和 GSAP 时间轴。

小啾老师复用 `video/shared/xiaojiu-rig`，装配参数以其 JSON 预设为准。角色承担引导、指向、思考、确认和过渡，不遮挡知识图形。眨眼、嘴型和翅膀动作必须使用独立部件，不用整张角色图替代可动部件。

### 4. 布局审核

先提供 HyperFrames 预览，再提供课程布局编辑器。用户可以逐镜移动、缩放和旋转元素，调整文字框、曲线端点和弯曲控制点。用户直接下载布局 JSON；无需先执行“应用 JSON”。收到 JSON 后写回正式配置，并保留已有动效。

### 5. 旁白和音画同步

用户在剪映中逐段生成 AI 旁白并留出自然气口，然后只需提供最终音频。音频是最终时间轴的权威来源。

根据音频生成或校正：

- 分镜起止时间。
- 句子和关键词出现时间。
- 图表、线条、数字和印章动作。
- 小啾嘴型、眨眼、点头和翅膀动作。

嘴型跟随发声区间，不要求逐音素口型；眨眼应自然、稀疏且避开关键强调瞬间。

### 6. 检查与渲染

修改 HyperFrames 工程后运行项目的完整检查，再生成关键帧或接触表检查：

- 元素重叠和越界。
- 文字换行与可读性。
- 角色部件错位、背景残留和左右翅膀错误。
- 动画是否过晚、过快、停留不足或画面长期空白。
- 16:9、目标分辨率、时长和音轨。

所有错误修复后才渲染 MP4。警告需要人工判断并记录是否接受。

### 7. 发布

成片使用 R2 保存，网站只引用远程视频地址，避免 Cloudflare Pages 的单文件大小限制。上传、覆盖远程对象、修改线上网站、提交和推送 GitHub 都需要当前任务中用户的明确授权。

## 自动验收脚本

`validate_episode.py` 接受项目根目录、课程工程目录和可选成片路径，输出人类可读报告，并以退出码区分通过与失败。

检查内容：

- 必要文档、HyperFrames 配置和入口文件是否存在。
- 旁白与分镜是否非空，分镜编号是否一致。
- 角色装配预设和共享资产是否可访问。
- 如果提供 MP4：是否包含视频流和音频流、是否为 16:9、时长是否有效、音轨是否存在可听信号。
- 如果检测到 HyperFrames 项目：执行或提示执行项目既有的 `check` 命令。

脚本只读取和报告，不上传、不覆盖、不删除文件。

## 失败处理

- 缺少课程题目：停止脚本定稿，列出缺失输入。
- 金融表述存在时效或准确性风险：先核验并修订，不直接动画化。
- 缺少最终旁白：可以制作布局预览，但不得宣称音画同步完成。
- 布局 JSON 与课程分镜不匹配：保留原配置并报告差异。
- HyperFrames 检查失败或媒体检查失败：不进入发布阶段。
- R2 或网站发布失败：保留本地成片和当前线上版本，不执行破坏性回退。

## 验证计划

1. 使用 Skill 初始化一个虚拟的新课程工作簿，确认字段能覆盖题目、旁白、分镜、布局、音频和发布信息。
2. 使用 `video/savings-lesson-01` 运行验收脚本，确认现有课程工程可被识别。
3. 使用当前 L1 成片验证分辨率、时长和音轨检测。
4. 运行 Skill Creator 的 `quick_validate.py`，确认 Skill 的命名、元数据和文件结构有效。
5. 检查 Skill 中没有硬编码密码、令牌、临时端口或用户下载目录。

## 非目标

- 不自动生成或替换课程知识内容。
- 不替代用户对脚本、布局和最终成片的审核。
- 不把剪映自动化为无人值守流程。
- 不在本次工作中重构 HyperFrames 课程工程架构。
- 不自动上传、部署、提交或推送。
